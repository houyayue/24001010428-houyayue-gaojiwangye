JSON 的四条硬规矩（写错就报错）

JSON 比 JS 对象严格得多，下面这些是新手最常踩的坑：

{
  "brand": "比亚迪",        // ✔ 键必须双引号包起来
  "price": 24.98,           // ✔ 数字不加引号
  "tags": ["新能源", "SUV"], // ✔ 数组用中括号
  "onSale": true,           // ✔ 只有 true / false / null，不能用 True / None
  "owner": { "name": "侯雅月" } // ✔ 可以嵌套
}

✘ 不允许：单引号、末尾多余逗号、注释、undefined、函数、变量、键不加引号。

JSON.parse("{'a':1}") → 报错：Unexpected token JSON.parse('{"a":1,}') → 报错：Unexpected token } {"a": undefined} → 序列化时该键直接消失

JS 值 → JSON 的「通关规则」

JS 里的值stringify 之后说明
字符串 / 数字 / 布尔原样保留基本类型直接变身
数组[ ... ]顺序保持不变
对象（不含函数）{ ... }键会被自动加上双引号
undefined键被丢弃对象里的 undefined 属性直接消失
函数 / Symbol键被丢弃JSON 只装数据，不装代码
NaN / Infinity变成 nullJSON 没有这两个词
Date 日期对象"2026-11-02T..."自动变成 ISO 格式字符串
nullnull表示「空」用 null，不是 undefined

方法速查

写法作用
JSON.stringify(obj)对象 → JSON 字符串（打包）
JSON.stringify(obj, null, 4)带 4 空格缩进的美化输出
JSON.stringify(obj, ['brand','price'])第二个参数传数组：只保留指定键（过滤）
JSON.parse(str)JSON 字符串 → 对象（拆包）
JSON.parse(str, function(k,v){})第二个参数 reviver：边拆边加工（如把日期串还原成 Date）
try { ... } catch(e) { ... }解析外部数据时必须包起来，防止坏数据让页面崩掉
