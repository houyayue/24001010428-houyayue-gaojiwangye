两种写法对照

左边是 async/await（像写同步代码一样读），右边是 Promise.then 链式；两者逻辑完全一样，Promise.all 的用法也相同。

// ===== ① 把 setTimeout 包装成 Promise =====
function task(name, ms) {
  return new Promise(function (resolve) {
    setTimeout(function () {
      console.log(name + ' 完成');
      resolve(name);        // 完成后"兑现"承诺
    }, ms);
  });
}

// ===== ② async/await 版：顺序读下来就是流程 =====
async function makeDumplings() {
  await task('买原料', 6000);
  await task('取原料', 2000);

  // 和面、和馅互不依赖 → 同时开始，等两个都完成
  await Promise.all([
    task('和面', 5000),
    task('和馅', 4000)
  ]);

  await task('包饺子', 4000);
  await task('吃饺子', 3000);
  console.log('开饭！');
}

// ===== ③ Promise.then 链式版：同样的流程用回调串起来 =====
task('买原料', 6000)
  .then(function () { return task('取原料', 2000); })
  .then(function () {
    return Promise.all([task('和面', 5000), task('和馅', 4000)]);
  })
  .then(function () { return task('包饺子', 4000); })
  .then(function () { return task('吃饺子', 3000); })
  .then(function () { console.log('开饭！'); });

知识点

概念说明
new Promise把 setTimeout 这类"回调式"异步包成 Promise，才能用 await
resolve()任务完成，通知 await 的地方可以往下走了
await等 Promise 完成，代码写起来像同步一样；只能在 async 函数里用
Promise.all([a, b])两个任务同时开始，全部完成才继续；总耗时取最长的那个
Promise.race([a, b])谁先完成就取谁（本例没用到，与 all 对比记忆）
串行 vs 并行买→取→包→吃必须排队（有依赖）；和面、和馅可以并行（无依赖）
耗时对比全串行需 24 秒，和面/和馅并行后约 20 秒，省下较短任务的时间
